# skincare-ingredient-advisor 設計方針

## アプリ概要

写真（またはセルフチェック入力）から肌に不足していそうな成分を判定し、
「今日の気温」「自分の肌質」を組み合わせて、対応する化粧水・美容液・クリーム・
乳液・パックを **ブランド・商品名つき** で提案するアプリ。

- 診断 → 不足成分の推定 → 商品カテゴリ別にブランド商品を提示、という流れ
- 気温や肌質が変わればおすすめも変わる（例: 気温が低い日は保湿系を優先、
  乾燥肌の人はもともと保湿系の優先度を上げる、など）
- ロジックは最初はシンプルなルールベース（if/switch）で実装し、後から
  重み付けや外部データ連携を検討する

## 使用技術

- Next.js (App Router) + TypeScript
- Tailwind CSS（レスポンシブ、スマホ優先）
- データ保存: ブラウザの IndexedDB（`idb`）を第一候補とする
  - 写真・診断履歴・プロフィール（肌質など）はすべて端末内保存
  - 気温は当面「今日の気温を手入力」で開始し、将来的に天気APIへの
    切り替えを検討する（その場合のみ外部通信が発生する設計にする）
- 成分×ブランド商品のマッピングはアプリ内データとして持たせ、
  画面から編集・追加できるようにする（既存の類似アプリと同じ方針）

## 画面構成（MVP）

1. **ホーム**: 今日の診断状況、各画面への導線
2. **診断**: 気になる部位のセルフチェック（毛穴/色ムラ/乾燥/テカリ/ハリ/肌荒れ等）
   + 今日の気温 + 肌質を入力
3. **結果**: 不足成分の推定結果と、朝晩それぞれで使う
   化粧水/美容液/クリーム/乳液/パックのブランド・商品提案
4. **商品データ**: 成分×ブランド商品の対応表を確認・編集
5. **設定**: 肌質・お気に入りブランドなどのプロフィール設定

## 開発の進め方

1. まず上記5画面の骨格（ナビゲーション + プレースホルダー内容）だけ作る
2. 骨格を確認してもらった上で、診断ロジック・商品データ・IndexedDB保存を実装する
3. 最終的に Vercel でデプロイして公開する
